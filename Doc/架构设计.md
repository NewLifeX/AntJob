# 架构设计 — AntJob 蚂蚁调度

> 版本：v4.5 | 日期：2026-10-18 | 从代码逆向整理

本文档描述 AntJob 的分层架构、核心组件、关键流程和设计决策。需求定义见[需求文档](需求文档.md)，实现状态见[功能清单](功能清单.md)。

---

## 1. 项目分层

AntJob 遵循 [NewLife 架构分层](../.github/instructions/development.instructions.md) 的务实渐进哲学：

- **阶段 2 — 数据层独立**：AntJob.Data 作为独立类库，被 Server/Web/Agent 三个入口共享
- **按需引入服务层**：Server 端 AntService 和 Web 端共享 AppService/JobService，通过 `<Compile Include Link>` 避免重复
- **混合分层**：Agent 端无独立服务层，Handler 直接对接 Provider 通信

```
┌──────────────────────────────────────────────┐
│              AntJob.Web (net10.0)             │  ← 表现层
│     Cube MVC + REST API + Startup             │
│     Link: AppService, JobService, Setting     │
├──────────────────────────────────────────────┤
│              AntJob.Server (net10.0)          │  ← 服务层+表现层
│     ApiServer(TCP) + AppService + JobService  │
│              AntJob.Agent (net10.0)           │  ← 客户端
├──────────────────────────────────────────────┤
│          AntJob.Extensions (netstandard2.x)    │  ← 扩展层
│       DataHandler / SqlHandler / SqlMessage   │
├──────────────────────────────────────────────┤
│          AntJob.Data (netstandard2.1)         │  ← 独立数据层
│   XCode Entity × 6: Model.xml → App/Job/...  │
├──────────────────────────────────────────────┤
│   AntJob (netstandard2.1/2.0/net461/net45)   │  ← 核心SDK
│ Scheduler / Handler / IJobProvider / Models   │
│ Providers: Network / File / Http              │
└──────────────────────────────────────────────┘
```

## 2. 核心组件

### 2.1 SYS — 核心调度引擎

| 组件 | 类型 | 职责 |
|------|------|------|
| `Scheduler` | class | 调度引擎：管理 `List<Handler>`，从 DI 发现处理器，TimerX 定时连接服务端 |
| `Handler` | abstract class | 处理器基类：生命周期 Init→Start→Acquire→Process→OnProcess→Execute→OnFinish，支持同步/异步双模 |
| `JobContext` | class | 任务上下文：Handler/Task/Result/Data/Error/Cost/Speed/Stopwatch |
| `IJobProvider` | interface | 作业提供者接口：Acquire/Produce/Report/Finish/GetJobs/SetJob |
| `JobProvider` | abstract class | 提供者基类：DisposeBase + IJobProvider + ITracerFeature + ILogFeature |
| `NetworkJobProvider` | class | 网络提供者：AntClient RPC → 调度中心，Peers 邻居发现 |
| `FileJobProvider` | class | 文件提供者：JobFile XML 持久化，离线单机调试 |
| `HttpJobProvider` | class | HTTP 提供者：ApiHttpClient 接入（编译排除，A/B 测试） |
| `AntClient` | class | RPC 客户端：ClientBase 子类，Login/GetJobs/AddJobs/Acquire/Report/Finish |
| `AntSetting` | Config | 客户端配置：Server(多地址主备)/AppID/Secret/Debug |
| `AntJobExtensions` | static class | DI 扩展：AddAntJob() → 注册 Scheduler/AntJobWorker/AntSetting |
| `TemplateHelper` | static class | 模板引擎：{dt}/{End}/{Message} 变量替换，Pool.StringBuilder 优化 |
| `TimeExpression` | class | 时间表达式：{dt+1M+5d:yyyyMMdd} 解析执行，y/M/d/H/m/s/w |
| `MessageHandler` | abstract class | 消息处理器：Topic 订阅，JSON 解码，逐条 ProcessItem |
| `CSharpHandler` | class | C# 脚本处理器：Mode=Time，基于 Roslyn 执行任务数据中的 C# 代码，脚本内可访问 ctx，返回值为成功数（net45 不支持） |
| `MessageOption` | class | 消息选项：DelayTime/Unique/AppId |

| `AppHistory` | Int64 雪花Id | AppID/Action/Success/TraceId（DataScale=time 分表） |
| `AppMessage` | Int64 雪花Id | AppID/JobID/Topic/Data/DelayTime（DataScale=time 分表） |

### 2.3 EXT — 扩展调度

| 组件 | 类型 | 职责 |
|------|------|------|
| `DataHandler` | abstract class | 数据窗口基类：Factory/Field/Where/OrderBy/Selects/KeepFirstPage，Mode=Data |

### 2.4 SRV — 调度中心服务

| 组件 | 类型 | 职责 |
|------|------|------|

## 3. 关键流程

### 3.1 任务调度生命周期

```mermaid
sequenceDiagram
    participant Agent as 执行节点
    participant Provider as NetworkJobProvider
    participant Server as 调度中心
    participant DB as 数据库

    Agent->>Provider: Start()
    Provider->>Server: AntClient.Login()
    Server->>DB: App/AppOnline 写入
    Server-->>Provider: LoginResponse

    loop 调度循环
        Provider->>Server: GetJobs()
        Server-->>Provider: Job[]
        Provider->>Agent: Handler.Init() → Start()

        Agent->>Provider: Acquire(count)
        Provider->>Server: Acquire(job, count)
        Server->>DB: 延迟→错误→切片→消息
        Server-->>Provider: Task[]

        Agent->>Agent: Process/ProcessAsync
        Note over Agent: OnProcess→Execute→OnFinish
        Agent->>Provider: Report+Finish
        Provider->>Server: 上报
        Server->>DB: JobTask 状态更新
    end
```

### 3.2 任务切片策略

```
JobService.Acquire(app, model, online):
  1. 检查应用启用 && 作业启用 && 非免打扰时段
  2. 获取全局 Redis 锁 antjob:lock:{jobId}（15s 超时）
  3. CheckDelayTask  → 优先分配延迟任务
  4. CheckOldTask    → 其次分配错误/超时重试
  5. 不足时按 Mode 生成新切片:
     - Time:    Cron.GetNext() 或 DataTime+Step
     - Data:    DataTime+Step，窗口 [DataTime, DataTime+Step)
     - Message: 从 AppMessage 拉取待消费消息
```

### 3.3 DataHandler 数据抽取

```
Init:
  自动识别 Field: DataScale含"time"/"timeShard" → 雪花Id主键 → MasterTime → UpdateTime → CreateTime
  Job.DataTime < 2000年 → GetMinDataTime()（按Field升序取首条记录时间）

OnProcess(ctx):
  while true:
    Fetch(ctx, ref row):
      WHERE Field >= DataTime AND Field < End
      ORDER BY Field ASC, 分页 BatchSize
      KeepFirstPage=true 时 row 始终=0（每次只查第一页）
    if 无数据: break
    ctx.Data = list → Execute(ctx) → Report(ctx, 处理中)
```

## 4. 关键设计决策

| 决策 | 说明 |
|------|------|
| UTC 通信 | 客户端↔服务端作业时间字段使用 UTC 传输，本地存储 LocalTime |
| 全局 Redis 锁 | `antjob:lock:{jobId}` 防止多服务端并发分配同一作业 |
| 双模处理器 | 自动检测是否重写 ExecuteAsync/ProcessAsync 等方法，选择同步/异步通道 |
| 僵死检测 | MaxInactiveTime + ConcurrentDictionary<Int32, DateTime> 跟踪，超时标记不存活 |
| 自动注册 | AutoRegistry=true，首次登录自动创建 App 记录并分配 Secret |
| 免打扰时段 | QuietTime="09:00-12:00,13:00-18:00" 多时段，含跨天 "23:00-02:00" |
| 多 TFM | 核心SDK: net45/net461/netstandard2.0/netstandard2.1；入口: net10.0 |
| 内嵌 Data.dll | AntJob.Web NuGet 包通过 `<BuildOutputInPackage>` 内嵌 AntJob.Data.dll |
| 密码保护 | SaltPasswordProvider(Algorithm=md5, SaltTime=60) 避免明文传输 |
| 雪花Id分表 | AppHistory/AppMessage 使用 Int64+DataScale=time，大数据量自动按时间分表 |

## 6. 关键机制补充

### 6.1 消息调度（Message 模式）时序

```mermaid
sequenceDiagram
    participant Producer as 生产方 JobService/SqlMessage
    participant DB as AppMessage
    participant Server as JobService.Acquire
    participant Agent as MessageHandler

    Producer->>DB: 写入消息（DelayTime=now+延迟，Unique 去重）
    Producer->>Producer: Job.MessageCount += n（异步回写）

    Agent->>Server: Acquire(job, topic, count)
    Server->>Server: 检查 job.Enable / 免打扰 / 全局锁
    Server->>DB: GetTopic(appId, topic, now, count*BatchSize)
    DB-->>Server: 待消费消息（DelayTime<=now）
    Server->>Server: 按 BatchSize 聚合为任务，Data=JSON[消息]
    Server->>DB: 删除已取消息，更新 MessageCount
    Server-->>Agent: Task[]

    Agent->>Agent: 解码 Data → String[] → ProcessItem(逐条)
    Agent-->>Server: Report / Finish
```

要点：

- 消息按 `BatchSize` 成批消费，一个任务对应一批消息，避免逐条消息产生任务膨胀。
- `MessageOption.DelayTime` 写入 `AppMessage.DelayTime`，`Acquire` 只取 `DelayTime <= now` 的消息，实现延迟消费。
- `MessageOption.Unique=true` 时短消息走缓存键 `antjob:{appId}:{topic}:{message}`（2 小时），长消息走 `AppMessage.Filter`。
- `MessageHandler` 每解码一条消息调用一次 `ProcessItem`，`Execute` 的返回值累加为成功数；失败的条目由基类记录错误并重试。

### 6.2 SQL `topic_` 列自动消息生产

`SqlHandler.ExecuteSql` 在执行 `Query` 片段后回调 `SqlMessage.ProduceMessage(dt, ctx)`：

1. 遍历结果集列名，凡以 `topic_` 开头的列均视为消息源；
2. 去掉前缀得到主题名（`topic_roleId` → `roleId`）；
3. 该列所有行值去重后，通过 `Handler.Produce(topic, messages, new MessageOption { Unique = true })` 投递；
4. 投递走当前作业提供者（RPC/HTTP），最终写入 `AppMessage`。

因此一条 SQL 即可完成“查询驱动”的消息分发，例如：

```sql
/*use membership*/
select id as topic_roleId, name from role where update_time>='{dt}' and update_time<'{End}'
```

该语句会把本次窗口内变更的角色 Id 去重后投递到 `roleId` 主题，由订阅该主题的消息处理器消费。

### 6.3 多调度中心主备与故障切换

- **客户端侧**：`AntSetting.Server` 支持逗号分隔多地址（默认 `tcp://127.0.0.1:9999,tcp://ant.newlifex.com:9999`）。`ClientBase` 维护服务器列表，连接/调用失败时自动切换到下一个地址；地址列表亦可由星尘注册中心动态下发。
- **服务端侧**：多个调度中心共享同一数据库，`JobService.Acquire` 通过 `antjob:lock:{jobId}` 分布式锁保证同一作业同时只有一个服务端在分配任务；分配前二次查询作业，避免实体缓存导致重复切片。
- **任务归属**：任务切片写入 `JobTask` 时记录 `Server/Client/ProcessID`，超时未上报的任务由 `CheckOldTask` 重新分配，实现执行节点故障转移。
- **在线管理**：`AppOnline` 记录实例心跳，`Worker` 每 10 秒清理超时在线记录；`GetPeers` 返回同应用在线实例，供客户端感知集群规模。

### 6.4 星尘注册中心集成

- **客户端**：`Scheduler.JoinAsync` 从容器获取 `IRegistry`，调用 `ResolveAddressAsync("AntServer")` 解析服务地址；解析成功时覆盖 `AntSetting.Server`，否则回退配置文件地址。
- **服务端**：`Worker.StartAsync` 启动 `ApiServer` 后调用 `_registry.RegisterAsync("AntServer", $"tcp://*:{server.Port}")`；`IRegistry` 缺失时跳过注册，单机部署无需星尘。
- **Web 端**：`Startup.Configure` 调用 `app.RegisterService("AntWeb", null, env.EnvironmentName)` 注册管理后台。
- **配置来源**：`AddStardust()` 负责建立星尘连接；未配置星尘时所有注册/解析均为空操作，系统退化为静态地址模式。

### 6.5 性能基准

基准项目位于 [Benchmark/AntJob.Benchmarks](../Benchmark/AntJob.Benchmarks)，完整报告见[核心组件性能测试](Benchmark/核心组件性能测试.md)。

核心结论（Release，.NET 10，i9-10900K）：

| 场景 | 单次耗时 | 说明 |
|------|---------:|------|
| 已解析时间表达式执行 | 34.5 ns | 建议按表达式缓存复用 |
| 模板替换（时间变量 / 消息变量） | 379 ns / 144 ns | 优化后（原 23.3 µs / 5.3 µs） |
| SQL 片段解析（1 条 / 4 条） | 404 ns / 1.41 µs | 线性增长，可按作业缓存 |

本轮优化：`TemplateHelper` 的占位符查找由区域性 `String.IndexOf(String)` 改为 `StringComparison.Ordinal` 与字符重载，模板替换提升 37~61 倍，分配量不变。
